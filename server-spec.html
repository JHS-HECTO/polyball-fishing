1. 개요

폴리볼 실험실 미니게임. iframe 임베드 + postMessage 통신. 게임 측은 유저를 식별하지 않으며 응모권 cap, 광고 SDK, 점수 누적은 폴리볼이 권위로 처리.

일일 응모권 cap

  • 하루 최대 3장
  • 게이지 채워 받기: 1번째 무료 / 2~3번째 광고
  • 황금물고기 추가: 광고 시청시 1장 (cap 내 포함)
  • 자정 자동 리셋

광고 종류

  • 보상형(rewarded) 만 사용
  • 인터스티셜 / 자동 광고 없음
  • 사용자가 명시적으로 요청한 시점에만 호출

2. 메시지 프로토콜 요약

방향typepayload의미
→ 부모FISH:READY(없음)게임 마운트 완료
→ 부모FISH:CLAIM_TICKETsource, adWatched응모권 적립 요청
→ 부모FISH:PLAY_AD_REWARDEDreason: 'progress' | 'golden'보상형 광고 요청
→ 부모FISH:SCORE_UPDATEtotal_score점수 갱신 (선택)
← 부모FISH:SET_PLAYERplayer, total_score플레이어 정보 주입
← 부모FISH:AD_REWARDED_COMPLETEDreason광고 시청 완료
← 부모FISH:AD_REWARDED_FAILEDreason, cause광고 실패/스킵
← 부모FISH:TICKET_GRANTEDcount, source적립 성공
← 부모FISH:TICKET_REJECTEDreasoncap 초과 / 광고 미시청 등

3. 클레임 cap 로직 (의사 코드)

function handleClaimTicket(userId, source, adWatched) {
  const daily = db.get('fishing_tickets_daily', userId, today());
  const ticketsToday = daily?.tickets_today ?? 0;

  if (ticketsToday >= 3)
    return { type: 'FISH:TICKET_REJECTED', reason: 'daily_cap_reached' };

  // progress 1번째만 광고 면제, 2~3번째 + golden은 광고 필수
  if (source === 'progress' && ticketsToday >= 1 && !adWatched)
    return { type: 'FISH:TICKET_REJECTED', reason: 'ad_required' };
  if (source === 'golden' && !adWatched)
    return { type: 'FISH:TICKET_REJECTED', reason: 'ad_required' };

  db.incr('fishing_tickets_daily', userId, today(), { tickets_today: 1 });
  grantTicket(userId, 1);
  return { type: 'FISH:TICKET_GRANTED', count: 1, source };
}

4. DB 권장 스키마

CREATE TABLE fishing_tickets_daily (
  user_id          BIGINT,
  date             DATE,
  tickets_today    INT NOT NULL DEFAULT 0,  -- 0~3
  golden_caught    INT NOT NULL DEFAULT 0,  -- 통계용
  progress_claimed INT NOT NULL DEFAULT 0,  -- 통계용
  PRIMARY KEY (user_id, date)
);

CREATE TABLE fishing_scores (
  user_id     BIGINT PRIMARY KEY,
  total_score BIGINT NOT NULL DEFAULT 0,
  updated_at  TIMESTAMP NOT NULL DEFAULT NOW()
);

자정 리셋은 date 키로 자연 처리. 별도 cron 불필요.

5. 표준 흐름 시나리오

1번째 무료 클레임

  1. 게이지 2000점 채움
  2. 사용자 "응모권 받기" 탭
  3. 게임 → CLAIM_TICKET { source: 'progress', adWatched: false }
  4. 서버 cap 검증 → TICKET_GRANTED
  5. 게임: 응모권 지급 완료 팝업

2~3번째 광고 후 클레임

  1. 게이지 다시 2000점 채움
  2. 사용자 "광고 보고 응모권 받기" 탭
  3. 게임 → PLAY_AD_REWARDED { reason: 'progress' }
  4. 폴리볼 광고 SDK → 광고 끝나면 AD_REWARDED_COMPLETED
  5. 게임 자동 → CLAIM_TICKET { source: 'progress', adWatched: true }
  6. 서버 → TICKET_GRANTED

황금물고기 잡힘

  1. 잡힘 → 광고 권유 모달
  2. "광고 보고 응모권 받기" 탭
  3. PLAY_AD_REWARDED { reason: 'golden' } → 광고 → AD_REWARDED_COMPLETED
  4. 게임 → CLAIM_TICKET { source: 'golden', adWatched: true }
  5. 서버 cap 검증 → TICKET_GRANTED 또는 REJECTED (cap 초과)

자정 리셋

  1. 날짜 변경 감지 (게임 1분 폴링 + focus 이벤트)
  2. 게임 측 카운터/게이지 자동 0
  3. 서버는 date 키로 자연 분리

6. 통합 체크리스트

  • iframe 임베드 (실험실 메뉴 진입점)
  • FISH:READY → SET_PLAYER 자동 응답 (현재 로그인 유저 닉/팀/누적점수)
  • FISH:PLAY_AD_REWARDED 핸들러 + 광고 SDK 호출 + 완료/실패 회신
  • FISH:CLAIM_TICKET 핸들러 + cap 검증 + DB 적립 + GRANTED/REJECTED 회신
  • FISH:SCORE_UPDATE 핸들러 + 점수 누적 (선택)
  • PIPA 동의 (앱 진입 단계, 게임 내부 X)
  • 만 14세 미만 처리 (정책팀 협의)
주의 게임은 CLAIM_TICKET / PLAY_AD_REWARDED 송신 후 1.5초 응답 없으면 UI 잠금 해제. 폴리볼 측은 가급적 1초 이내 응답 권장. 실패 케이스는 반드시 REJECTED 또는 AD_REWARDED_FAILED 명시.
